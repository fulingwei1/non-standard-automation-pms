# 非标自动化 PMS 重构执行清单（止血版 + 演进版）

> 目标：先把“假可用”变“真可用”，再做结构瘦身。
> 产出优先级：稳定性 > 可维护性 > 性能 > 新功能。

---

## 0. 当前基线（已确认）

- 后端运行时路由总数：**2504**（唯一路径 **2062**）
- 路由聚合文件：`app/api/v1/api.py`（超大聚合，try/except 吞错）
- 兜底路由：`app/api/v1/endpoints/stub_endpoints.py`（未实现接口返回 200/空数据）
- 前端页面 API 集成（脚本结果）：
  - 完全集成：**209 / 566（36.9%）**
  - 部分集成：30
  - 未集成（仅 mock）：62
  - 未知：265
- 启动日志明确失败模块：
  - 认证子模块：`No module named 'qrcode'`
  - ITR 模块：`No module named 'app.models.customer'`

---

## Phase 0（3~5 天）——先止血

## Day 1：禁止“假成功”

### 任务
1. 在生产环境禁用 `stub_endpoints` fallback。
2. 开发环境 fallback 也要改成显式 501（带 `_stub=true` 但 HTTP 501）。
3. 给所有 stub 命中打告警日志（路径、方法、调用人）。

### 验收
- 未实现接口不再返回 200。
- 前端能看到明确错误而不是“空数据成功”。

---

## Day 2：修复已知硬故障

### 任务
1. 修复认证模块缺失依赖：`qrcode`（requirements/venv 同步）。
2. 修复 ITR 导入路径问题（`app.models.customer`）。
3. 启动时关键模块加载失败应 fail-fast（退出进程），不能 print 后继续跑。

### 验收
- `app.main` 启动时 auth/itr 不再报错。
- 不存在“模块加载失败但服务继续运行”的情况。

---

## Day 3：路由/前后端对账自动化

### 任务
1. 增加 CI 检查：前端请求路径 vs OpenAPI 路径对账。
2. 新增路由注册检查：新增 endpoint 文件但未注册即 CI fail。
3. 增加 stub 命中率报表（每日）。

### 验收
- CI 中能直接看到“前端调用但后端不存在”的路径清单。

---

## Day 4~5：前端先清“部分集成”30 页

### 任务
1. 先处理“有 API 但仍有 mock/fallback”页面（30 个）。
2. 建立页面分级：
   - P0：核心交易链路（项目/销售/采购/审批）
   - P1：看板统计
   - P2：低频工具页

### 验收
- P0 页面不再包含 mock fallback。
- 真实 API 失败时能给出可观察的错误提示。

---

## Phase 1（1~2 周）——拆聚合器，降耦合

## Week 1：后端路由拆域

### 任务
将 `app/api/v1/api.py` 拆为：
- `router_registry/auth.py`
- `router_registry/project.py`
- `router_registry/sales.py`
- `router_registry/procurement.py`
- `router_registry/production.py`
- `router_registry/quality.py`
- `router_registry/system.py`

每个 registry 只做：导入 + include_router，不写业务逻辑。

### 验收
- `api.py` 行数下降 70%+。
- 任一域加载失败可精准定位，不再全局吞错。

---

## Week 2：前端 API 层拆域

### 任务
1. 将 `frontend/src/services/api.js`（巨型 barrel）改为域入口：
   - `services/api/project/index.ts`
   - `services/api/sales/index.ts`
   - ...
2. 页面按域只引域 API，不再全局导出。

### 验收
- 新页面不允许 `import * from "services/api"`。
- 构建体积和冷启动导入链可观测下降。

---

## Phase 2（2~4 周）——瘦身 + 稳定化

## 任务包 A：删除高置信死代码
- 删除/归档：
  - `app/api/v1/endpoints/template_configs/apply.py`
  - `app/api/v1/endpoints/template_configs/crud.py`
  - `app/api/v1/endpoints/base_crud_router.py`

## 任务包 B：依赖瘦身
- 前端先删（高置信 0 引用）：
  - `@dnd-kit/utilities`
  - `@radix-ui/react-popover`
  - `@radix-ui/react-scroll-area`
  - `@radix-ui/react-separator`
  - `@radix-ui/react-tabs`
  - `zustand`
- 后端统一 HTTP 客户端（`requests` -> `httpx`）。

## 任务包 C：AI 功能插件化
- 拆分为 extras（`.[ai]`），默认核心包不带重依赖。
- 用 feature flag 控制运行时启用。

---

## 每周固定质量闸门（必须执行）

1. 路由注册完整性检查（新增 endpoint 必注册）
2. 前后端 API 对账（path + method）
3. stub 命中率趋势（应持续下降）
4. 核心链路 e2e（登录→项目→采购→审批）
5. 构建与测试：
   - 前端：`pnpm build` + `pnpm test:run`
   - 后端：关键 API smoke + pytest 子集

---

## 回滚策略

- 每个阶段单独分支：`refactor/phase0`, `refactor/phase1`, `refactor/phase2`
- 每个阶段必须有可回滚 tag：`refactor-p0-done` 等
- 任何影响 auth/approval 的改动必须灰度（先 dev/staging）

---

## 最终目标（量化）

- 4 周内将“完全集成页面占比”从 36.9% 提升到 **70%+**
- stub 命中率降到 **< 1%**（开发环境）/ 生产环境 **0**
- `api.py` 单文件职责拆解完成，故障定位时间缩短 50%+
- 删除高置信死代码和无引用依赖，降低维护噪音

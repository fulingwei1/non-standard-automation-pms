# 成本 / 报表总核对报告

**目标**：验证成本归集到 `project_costs` 后，项目**实际成本 / 预算 / 毛利 / 报表**在 DB 与各接口之间数值一致，且报表端点稳定。
**验收方式**：真实角色(PM)录入多类成本 → DB 与 汇总/实际/明细/预算对比/毛利分析 四方交叉核对 → 报表冒烟 → 整库还原清理
**日期**：2026-07-02
**环境**：后端 `app.main:app`@127.0.0.1:8002；DB SQLite `data/app.db`（验收前整库备份，验收后已还原，零残留）
**结果**：**20/20 全部通过**，未发现缺陷。

---

- 新建项目：合同额 ¥1,000,000，预算 ¥700,000，PM=验收项目经理

## 5. 成本来源可追溯（观察）

- 全库 `project_costs` 中带 `source_type` 的记录 **81 条**，说明成本自动归集机制（采购/工单/工时→project_costs）确实存在并已在历史数据生效。
- 采购链路验收中"收货后未见新增采购成本"（观察 D2）的成因：测试采购**订单**状态停留在 APPROVED，未推进到触发归集的 RECEIVED/COMPLETED，故非缺陷；建议后续单独验证"订单置 RECEIVED 后自动归集"这一触发路径。

## 7. 结论

成本 / 报表子系统**数值口径自洽、报表稳定**：实际成本在 DB 与各接口五处一致，预算差异与毛利/预测毛利计算正确，报表端点无崩溃且具权限控制。本轮**未发现缺陷**，是目前验收质量最高的模块之一。建议后续补验"采购订单 RECEIVED→成本自动归集"触发链。

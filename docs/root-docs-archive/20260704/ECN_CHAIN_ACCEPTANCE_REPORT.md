# 设计变更(ECN)链路端到端验收报告

**链路**：建变更单 → 影响物料/成本评估 → 提交审批 → CCB 审批 → 执行 → 物料处置/成本记录 → 验证 → 关闭 → 同步项目/BOM/采购
**验收方式**：真实角色(变更工程师/CCB 审批人)登录 → 逐环节调真实 API → 每步核对数据库 → 正向 + 反向 → 整库还原清理
**日期**：2026-07-02
**环境**：后端 `app.main:app`@127.0.0.1:8002；DB SQLite `data/app.db`（验收前整库备份，验收后已还原，零残留）
**结果**：链路**前段（建单/影响物料/成本记录）跑通**；审批及其后续环节被**审批模板缺失**阻断。检查项 **12/17 通过**，未通过项均由 2 个已确认缺陷导致。

## 3. 越权 / 反向验收

| 用例 | 期望 | 结果 |
|---|---|---|
| N1 无 ecn:create(销售员)建变更单 | 403 | ✅ 403 |
| N2 无 ecn:approve(工程师)执行审批动作 | 403 | ✅ 403 |
| N3 无关角色(销售员)验证变更 | 应 403 | ❌ 非 403（执行/验证端点无权限校验，见 ECN2） |
| N4 未携带 token 访问 | 401 | ✅ 401 |

**RBAC 现状**：ECN 的**发起/提交/审批**（core + approval）有权限闸门（ecn:create/submit/approve）；**执行/验证/关闭/物料处置/成本记录**（execution/material_impact/cost_impact）**无 require_permission**。

---

## 4. 发现问题（FINDINGS）

| 编号 | 严重度 | 环节 | 问题 | 影响 |
|---|---|---|---|---|
| **ECN1** | 高 | ECN 审批 | 提交 ECN 审批报『审批模板不存在: **ECN_STANDARD**』，且 `/ecns/approval/submit` **HTTP 仍返 200**（错误藏在 body.errors） | ECN 审批流不可用，执行/验证/关闭全链受阻；**与合同审批模板缺失(F1)同源** —— 审批模板未随种子初始化 |
| **ECN2** | 中 | ECN 执行阶段 | `execution.py / material_impact.py / cost_impact.py` 端点无 `require_permission`（仅 get_current_active_user），任意登录用户可执行/验证/关闭/处置/记成本 | 变更执行环节缺职责分离（发起/审批已管控，执行开放） |

> 修复建议：ECN1 初始化 `ECN_STANDARD` 审批模板（并统一排查所有审批模板种子）、提交失败返 4xx 而非 200；ECN2 为 execution/material/cost 端点补 `ecn:execute`/`ecn:verify` 等权限。

## 6. 结论

设计变更(ECN)链路**前段（建单、受影响物料、成本记录）功能正常**，字段与数据落库正确，状态机对越序流转拦截有效，发起/提交/审批具备权限控制。但**审批模板 `ECN_STANDARD` 缺失导致审批及后续执行/验证/关闭无法进行**（ECN1，与合同审批 F1 同源，属系统性审批模板初始化缺失），且执行阶段缺 RBAC（ECN2）。

**待修复**：ECN1（高，补审批模板+失败不返 200）、ECN2（中，执行阶段补权限）。

# 生产/售后现场缺料提报链路端到端验收报告

**链路**：生产工单现场缺料提报 + 售后现场缺料提报 → 统一缺料处理系统（确认→处理→解决）→ 缺料检测/预警
**验收方式**：真实角色(生产计划员/售后主管/处理人)登录 → 逐环节调真实 API → 每步核对数据库(现场载体关联) → 正向 + 反向 → 整库还原清理
**日期**：2026-07-02
**环境**：后端 `app.main:app`@127.0.0.1:8002；DB SQLite `data/app.db`（验收前整库备份，验收后已还原，零残留）
**结果**：两个现场入口**端到端贯通并汇入统一缺料系统**。检查项 **14/15 通过**，唯一未通过为已确认缺陷（提报无 RBAC）。

## 2. 正向主链路（两个现场入口 → 统一处理）

| 段 | 环节 | 结果 | 三方核对 |
|---|---|---|---|
| A | 生产工单现场提报缺料 | ✅ | `shortage_reports` 落库，**work_order_id=52**，material_id=1，status REPORTED |
| A | 处理闭环 | ✅ | REPORTED→CONFIRMED→HANDLING→**RESOLVED** |
| B | 售后现场提报缺料 | ✅ | `shortage_reports` 落库，**machine_id=4**，status REPORTED |
| B | 处理闭环 | ✅ | REPORTED→**RESOLVED** |
| C1 | 汇入同一系统 | ✅ | 生产+售后两张缺料单同存于 `shortage_reports` |
| C2 | 来源可追溯 | ✅ | 按 work_order_id / machine_id 均可回溯提报来源 |
| C3 | 检测/预警 | ✅ | inventory-warnings/check 与 detection/alerts 均 200，不崩溃 |

**结论**：生产车间与售后现场两个来源的缺料提报，通过统一的 `shortage/handling/reports` 入口进入同一处理系统，携带各自现场载体（工单/机台），并走完确认→处理→解决闭环，来源可追溯。

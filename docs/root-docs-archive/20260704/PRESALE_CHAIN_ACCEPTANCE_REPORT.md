**环境**：后端 `app.main:app`@127.0.0.1:8002；DB SQLite `data/app.db`（验收前整库备份，验收后已还原，零残留）

## 2. 正向主链路（单据流转与三方核对）

| # | 环节 | 操作角色 | 结果 | 三方核对 |
|---|---|---|---|---|
| 1 | 售前支持申请 | 销售 | ✅ | `presale_support_ticket` 落库，ticket_type=SOLUTION，status PENDING |
| 2 | 接单 | 售前工程师 | ✅ | status→**ACCEPTED**，assignee_id=工程师 |
| 3 | 更新进度 | 售前工程师 | ✅ | progress 60% |
| 4 | 技术方案 | 售前工程师 | ✅ | `presale_solution` 挂 ticket_id，status DRAFT |
| 5 | 方案评审 | 售前主管 | ✅ | review_status→**APPROVED** |
| 6 | 交付物登记+评审 | 售前工程师/主管 | ✅ | 交付物创建并评审 |

**亮点——报价三位一体绑定**：从售前方案发起报价，报价版本正确回填 `presale_solution_id` + `presale_ticket_id`，打通"售前方案 ↔ 报价"的闭环；且绑定时**校验"方案客户必须与报价客户一致"**（不一致返 400"售前方案与客户不匹配"，为一项有效数据一致性控制）。

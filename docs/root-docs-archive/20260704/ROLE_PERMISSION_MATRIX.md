## 3. 已验证有效的越权 / 职责分离控制 ✅

| 控制点 | 表现 |
|---|---|
| 销售员不能签合同/开票 | 403（`contract:sign` / `finance:read` 缺失） |
| 合同签署数据范围 | 非归属人无权签署（数据 scope 校验） |
| 报价审批走工作流指定审批人 | 审批人绑定组织账号，销售员自审 403 |
| 采购订单审批 | 要求创建人直属上级；自审批被拒（403） |
| 收货数量 | 不能超订单/送货剩余（400） |
| 采购员/PM 不能入库、开票 | 403（`inventory:create` / `finance:read` 缺失） |
| 生产报工数量 | 不能超工单计划数（400） |
| 外出派工 | 权限分级(read/create/assign/execute) + 状态机；工程师建单 403、未派工完成 400 |
| 发货/签收状态机 | 未审批发货 400、未发货签收 400 |
| 未登录访问 | 全模块 401 |
| 成本/毛利/预算 | 数值口径自洽（DB↔接口五方一致） |

## 5. 附：跨链路缺陷总台账（7 份报告汇总）

| 编号 | 严重度 | 模块 | 缺陷 |
|---|---|---|---|
| F1 | 高 | 销售 | 合同审批模板 `SALES_CONTRACT_APPROVAL` 缺失，提交失败仍返 HTTP 200 |
| F3 | 高 | 销售 | 开票金额可超合同额，无累计上限校验 |
| F2 | 中 | 销售 | 合同签署无\"须先审批通过\"状态前置 |
| P1 | 高 | 项目 | `project_risks` 表未建，`POST /projects/{id}/risks` 报 500 |
| D1 | 高 | 采购 | 采购申请审批端点无权限校验（可自审批） |
| PR1 | 高 | 生产 | `quality.py` 多处 `current_user["id"]`（User 非 dict）→ 质检/缺陷/预警/返工写接口全崩 |
| PR2 | 高 | 生产 | 生产链路整体无 RBAC |
| SH1 | 高 | 发货 | 发货单端点整体无 RBAC |
| AS1 | 中 | 售后 | 工单号 `SUP-日期-项目` 无序列，同项目同日二次建单撞唯一约束 → 500 |

**共性问题**：
1. **RBAC 缺失集中在生产/发货/售后工单本体**——这三个模块的审批/操作对任意登录用户开放，是最高优先级加固点。
2. **多处以 500 崩溃**（项目风险表缺失、质检 `current_user["id"]`、工单号唯一冲突）本应为 4xx 或不该发生——反映健壮性与错误处理不足。
3. **审批模板/触发缺失**（合同审批模板未初始化、采购成本归集依赖订单状态推进）——需补种子数据与流程串联。

---

## 6. 建议修复优先级

1. **P0（数据/接口直接崩溃）**：PR1 质检 `current_user["id"]→.id`；P1 建 `project_risks` 表；AS1 工单号加序列。
2. **P1（权限/职责分离）**：生产(PR2)/发货(SH1)/售后工单/采购申请审批(D1) 补 `require_permission` 并区分创建/审批/执行权限。
3. **P2（业务规则）**：F3 开票金额上限、F1 合同审批模板初始化+失败不返 200、F2 签署前置审批。
